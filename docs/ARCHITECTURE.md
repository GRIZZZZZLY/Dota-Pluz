# Архитектура Dota 2 Copilot

Документ описывает слой Copilot поверх базового приложения d2bg v2. Как устроено само d2bg,
написано в `docs/DESIGN.md`. Что приложение трогает в системе, написано в `docs/SAFETY.md`.
Порядок дальнейшей работы описан в `docs/IMPLEMENTATION_PLAN.md`. Техническое задание лежит в
`DOTA2_COPILOT_TZ.md`.

Состояние на 2026-11-07: выполнены этапы 0, 1 (каркас), 2 (офлайн-Copilot на `/compact`) и 3
(драфт: чтение экрана отдельным процессом `d2bg-cv` и ручная правка).

## Основа

База — `Tajaddin/dota2-build-generator`, ветка `main` (`9d8cdfb`) плюс ветка автора
`fix-live-draft` (`0cfd08c`). Эта ветка — fast-forward от `main` с тестами. Она добавляет то, что
GSI реально присылает игроку в ranked: своего героя и сторону, баны из событий чата, союзников и
замеченных врагов с миникарты после загрузки. В ней же лежат две анонимизированные записи
настоящих игр (`tests/d2bg/fixtures/`). Код v1 (`main.py`, `logic/`, `ui/`, `ml/`) не используется.

## Поток данных

```text
Dota 2 --POST /gsi--> LiveEngine.ingest            (таймеры, сборки, алерты, драфт; скилл — через builds/skills.py)
                            |
                            +-- on_payload --> Services._on_payload
                                                 |-- Recorder.write        сырой GSI в .jsonl.gz (как было)
                                                 +-- Copilot.observe
                                                       |-- build_context   GameState + драфт движка -> GameContext
                                                       |-- diff_events     предыдущий и новый контекст -> события
                                                       |-- CopilotStore    matches, gsi_events_index (SQLite, WAL)
                                                       |-- baseline.recommendations   кандидаты: скилл, талант, предметы, выкуп
                                                       |-- baseline.rejection         Validator: допустимо ли действие сейчас
                                                       +-- CopilotStore    recommendations: suggested -> followed / expired / unknown / dismissed

d2bg-cv (отдельный процесс, по желанию) --GET /api/copilot/status--> идёт ли драфт настоящей игры?
        да: снимок монитора -> слоты (калибровка) -> шаблоны героев -> 2 согласных кадра
        --POST /api/copilot/draft/observation (только с этого ПК, с GSI-токеном)--> LiveEngine.add_screen_draft
Страница Draft (доска игрока) --POST /api/copilot/draft/manual--> LiveEngine.correct_draft (правка игрока главнее)

GET  /api/copilot/status                         GSI, режим (game/demo/replay), патч, GameContext, журнал, отказы валидатора
GET  /api/copilot/recommendations?status=...     журнал рекомендаций текущего или указанного матча
POST /api/copilot/recommendations/{id}/dismiss   игрок скрыл совет
web /compact -> CopilotPanel                     советы, причины, недостающее золото, ETA, «Как купить», состояние данных
```

Copilot подключён через существующий хук `LiveEngine(on_payload=...)`. Если Copilot падает, ошибка
попадает в поле `error` ответа `/api/copilot/status`, а живой экран продолжает работать. На этапе 2
движок изменён в одном месте — выбор следующего скилла (см. решение C7).

## Компоненты ТЗ и их реализация

| Компонент из ТЗ | Где он сейчас | Комментарий |
|---|---|---|
| GSI parser | `gsi/state.py` (база) | Переиспользован без изменений |
| GameStateNormalizer | `copilot/pipeline.py: build_context` | Каждая группа полей помечена источником |
| EventBus | `copilot/pipeline.py: diff_events` + `Copilot.observe` | Синхронная функция. Потребитель пока один, шина не нужна |
| Recorder / SQLite | `gsi/recorder.py` (база) + `copilot/store.py` | Сырой GSI лежит в `.jsonl.gz`. В SQLite лежат только ссылки (файл и номер кадра) |
| StateFusion | драфт `LiveEngine` + `build_context` | Драфт: GSI, затем экран (`d2bg-cv`) только добавляет героев, затем правка игрока (убранное им не возвращается). Источник группы `draft` — самый слабый из участвовавших: `manual`, `cv` или `gsi` |
| DraftCVAdapter | `src/d2bg_cv/` (отдельный пакет и процесс) | `recognize.py` (из Dota Assist: порог, отрыв от второго, 2 кадра, формула уверенности; своё: скольжение по портрету, текстура пустых слотов, память слотов), `calibrate.py` (верхняя полоса, на каждом кадре), `cli.py` (захват `mss`, только во время драфта) |
| CandidateGenerator | `copilot/baseline.py: recommendations` | Скилл и талант по pro-данным, основной предмет по pro-сборке, ситуативный и защитный предмет по правилам против видимых врагов, защита выкупа |
| Validator | `copilot/baseline.py: rejection` | Последняя проверка для любого источника: тот же матч, ссылки только на факты контекста, правила рангов, очко навыка, ярус таланта, предмет существует и не куплен, окно выкупа |
| DecisionJournal | таблица `recommendations` | Одна активная рекомендация на тип и категорию. При замене старая получает `followed`, если игра показала, что игрок так сделал, иначе `expired`; талант — `unknown` |
| Jev / Groq / DeepSeek | нет | Этапы 4 и 5 |

## Контракты (`copilot/models.py`)

`GameContext` — единый источник правды. Все поля необязательные. Поле `sources` хранит источник
для каждой группы полей: `match`, `patch`, `hero`, `position`, `draft`, `economy`. Возможные значения:
`gsi`, `cv`, `opendota`, `manual`, `snapshot`, `unknown`. Неизвестное остаётся `None` или `unknown`.

- `time_s` — игровые часы так, как их видит игрок (`map.clock_time`, до горна отрицательные). Системное
  время в контекст не попадает. Отсчёт OpenDota тоже идёт от горна, поэтому таймкоды совпадут.
- `learned_skills` — только собственные способности героя (по `heroes.json`) с рангом. GSI в реальной
  игре присылает ещё и косметику с уровнями (`plus_high_five`, `seasonal_dark_carnival_pie` на 5-м уровне),
  её в контексте нет. `ultimates` — способности с GSI-флагом `ultimate`. `talents` — `talent_1..8` из GSI.
- `gold_targets` — суммы золота, при пересечении которых меняется совет о выкупе (с 30-й минуты).
  Пересечение даёт событие `gold_threshold_crossed`.
- `allies` и `enemies_visible` заполняются только внутри матча. Вне матча движок помнит прошлый
  драфт, но в контекст он не попадает.
- `draft_confidence` — самое слабое совпадение среди героев, прочитанных с экрана, с поправкой на долю
  нечитаемых слотов (формула Dota Assist). `draft_unknown_slots` — слоты, где герой есть, но не прочитан:
  в UI это «?», подстановки нет.
- `evidence_ids` — словарь фактов, на которые разрешено ссылаться: `hero:<key>`, `build:<key>` (есть
  pro-сборка), `level:<n>`, `gold:<n>`, `buyback_cost:<n>`, `inventory:<item>` (инвентарь, рюкзак,
  тайник), `ally:<key>`, `enemy:<key>`. Рекомендация, которая ссылается на отсутствующий факт,
  отбрасывается. Если причины совета изменились (продан компонент, замечен другой враг), показанная
  запись заменяется новой, даже когда кандидат тот же.

`CopilotEvent`: `match_started`, `phase_changed`, `hero_selected`, `skill_point_gained`,
`skill_leveled`, `item_changed`, `draft_changed`, `death`, `respawn`, `match_finished`. Новый матч
(в том числе запуск приложения посреди игры) даёт только `match_started`: текущее состояние
восстанавливается как есть и не превращается в поток старых событий. Перенос предмета в тайник
событием не считается.

`Recommendation` повторяет поля из раздела 4 ТЗ и добавляет `category` для предметов: `core`,
`situational`, `defensive`, `buyback` (ТЗ F4.2). `confidence_kind` объясняет, что означает
`confidence`: `none`, `pro_pick_share` (доля pro-матчей с этим выбором) или `unverified_model_score`.
Это никогда не вероятность победы. `id` вычисляется из матча, типа, кандидата и `context_hash`,
поэтому повторный прогон того же матча ничего не дублирует.

## Хранилище (`copilot/store.py`)

Файл `%LOCALAPPDATA%\d2bg\copilot.sqlite3` (в тестах — `D2BG_HOME`). Режимы `WAL`,
`synchronous=NORMAL`, `foreign_keys=ON`. Миграции — список SQL-скриптов, номер версии хранится в
`PRAGMA user_version`. Каждый скрипт выполняется один раз в своей транзакции.

| Таблица | Содержимое | Индексы |
|---|---|---|
| `matches` | матч, источник (`game`/`demo`/`replay`), герой, сторона, патч, первое и последнее появление, файл записи | PK `match_id` |
| `gsi_events_index` | событие, игровое время, деталь, файл записи и номер кадра | уникальный `(match_id, type, detail, time)`, `(match_id, game_time_s)` |
| `recommendations` | все поля `Recommendation` и `created_at`; `category` — миграция 2 | `(match_id, game_time_s)`, `type`, `created_at`, `(match_id, status)` |
| `draft_observations` | миграция 3: чтение экрана (`cv`) и правки игрока (`manual`), уверенность, нечитаемые слоты, полное наблюдение в JSON | `(match_id, created_at)` |

Запись идёт только при событиях, а не на каждом пакете GSI. При старте нового матча все ещё открытые
советы прошлых запусков закрываются: после перезапуска приложения посреди игры журнал не показывает
устаревшее. Замер после этапа 2 на демо-матче (2 286 пакетов, этот ПК): `ingest` без Copilot —
p50 0.41 мс, p95 0.48 мс; с Copilot и файловой SQLite — p50 0.50 мс, p95 0.66 мс. Ориентир ТЗ — 500 мс.
Интерфейс опрашивает советы раз в 0.5 с.

## Принятые решения и отличия от ТЗ

| # | Решение | Почему |
|---|---|---|
| C1 | Основа — `main` плюс `fix-live-draft` | Ветка того же автора с тестами и реальными записями. Без неё драфт игрока из GSI почти пуст |
| C2 | Миграции через `PRAGMA user_version` вместо Alembic | ТЗ допускает эквивалент. Alembic потянул бы SQLAlchemy ради трёх таблиц |
| C3 | Без отдельной шины событий | Потребитель один. Шину стоит добавить, когда появится второй независимый потребитель |
| C4 | Таблицы `draft_observations`, `provider_calls`, `postmatch_*`, `practice_goals` добавляются миграциями своих этапов | Пустые таблицы впрок пришлось бы менять позже |
| C5 | Флаги функций — в существующем `settings.json`, а не в таблице `feature_flags` | Настройки уже есть, атомарно сохраняются и проходят валидацию |
| C6 | Демо и replay пишутся в журнал с меткой источника | Конвейер проверяется без игры. В UI метка не даст выдать демо за реальность |
| C7 | Исправлен базовый подсчёт очков навыков и выбор следующего скилла в `LiveEngine` | В реальной игре GSI присылает косметические способности с уровнями до 5, и `unspent_skill_points` всегда давал 0: напоминание о скилле не срабатывало. Индекс pro-порядка тоже был сдвинут. Теперь считаются только способности героя, а выбор идёт через `builds/skills.py`, общий для движка и Copilot |
| C8 | Ранги проверяются только когда данные и GSI согласны (обычная 4 ранга, ульта 3) | В `abilities.json` нет явного максимума ранга. Где правило не подтверждается (орбы Invoker), совета нет вместо догадки |
| C9 | Категория и русская причина контр-предметов — в `data/knowledge/counter_items.json` | Это данные, а не логика. Английская причина базы осталась |
| C10 | На `/compact` панель Copilot заменила список следующих предметов и строки про скилл и выкуп | ТЗ просит на компактном экране следующий скилл, предмет, причины и золото. Полные списки остались на странице Live |
| C11 | Чтение экрана драфта — отдельный пакет `d2bg_cv` и отдельный процесс; ядро его не импортирует | Решение пользователя (2026-11-07): автозахват вместо вставки скриншота. Правило «ядро не снимает экран» осталось в силе; захват разрешён только `d2bg_cv/cli.py` и проверяется `test_cv_safety.py` |
| C12 | Захват только когда сервер сообщает `hero_selection` или `strategy` настоящей игры; без второго GSI-сервера | ТЗ: «запускать захват только во время экрана драфта», «не тянуть второй независимый GSI-сервер» |
| C13 | Шаблоны — портреты героев с публичного CDN Valve, без извлечения из файлов игры (VPK, как у Dota Assist) | Приложение не читает файлы игры. Цена: арканы и персоны не узнаются и становятся «?» |
| C14 | Пропуск слота в колонке восстанавливается по шагу колонки | У Dota Assist пропущенный слот молча терялся (дополнение нулями в конце). Нашёл синтетический тест |
| C15 | Удалённых героев доска присылает явно (`removed`), сервер их не вычисляет | Иначе бан, пришедший между синхронизациями доски, считался удалённым. Нашёл e2e-тест |
| C16 | Экран драфта — «верхняя полоса»: по 5 скошенных карточек пиков на сторону, у каждой полоса цвета игрока. Пустая карточка стоит на полосе, выбранная опускается под неё, поэтому раскладка определяется заново на каждом кадре и для каждой карточки. Полосы отличаются от подчёркиваний ников и ярких пятен портретов одинаковой шириной; бледную полосу восстанавливает зеркало. Внутренность карточки ищется скольжением по портрету CDN в трёх масштабах (0.62/0.66/0.70); пустая карточка отличается от занятой по текстуре (лапласиан) | Реальные кадры 1080p Turbo (2026-11-07): на 9 кадрах 0 неверных героев, на стадии планирования 10 из 10 (совпало с GSI-записью матча). Кадр без героев и ников — фикстура `tests/d2bg/fixtures/draft_topbar_1080p_bans.png`; кадры с портретами в репозиторий не кладутся (арт Valve) |
| C17 | Калибровка по боковым колонкам из Dota Assist удалена | На реальном экране её нет; путь был хрупким (сдвиг на 1–2 px ломал сравнение). Если у ranked All Pick окажется другой экран, раскладка добавится по скриншотам |
| C18 | Сборки для Turbo собираются самим приложением: раз в день, в фоне, до ~900 запросов к бесплатному OpenDota — свежие публичные игры Turbo со средним рангом «Божество» и выше. У всех игр берутся финальные предметы, у разобранных OpenDota (примерно каждая восьмая) — покупки со временем: стартовые предметы и первые крупные предметы. Хранятся последние 21 день (`turbo_matches.jsonl.gz`), итог по героям — `turbo_builds.json` с размером выборки. Отключается в Настройках | Решение пользователя (2026-11-07): брать данные сильных игроков, а не его собственные. Готовых сборок Turbo нет ни у OpenDota, ни у STRATZ (у STRATZ фильтры закупок — только ранг и позиция); про-сборки — для обычного режима, где золото идёт примерно вдвое медленнее |
| C19 | Подсказки поверх Dota — три маленьких окна WebView2 (скилл, пики, предметы) вместо одной панели; окно без подсказки полностью прозрачно (альфа 0), а не скрыто: показ окна в Windows забирает фокус у игры. Содержимое — `GET /api/copilot/hud` из данных GSI; Turbo определяется по пассивному золоту за ~12 с после горна (Turbo 180 в минуту, обычная ~95; число GPM из GSI режим не различает) | Решение пользователя (2026-11-07): «подсказки по месту», и остаться на WebView2. Замер на его ПК: оверлей на WebView2 ≈ 470 МБ, окно Tk ≈ 30 МБ, сервер ≈ 70 МБ; переписывание на Rust/Tauri памяти не экономит — Tauri на Windows тоже WebView2 |
| C20 | Облачные модели только переранжируют кандидатов правил: Jev выбирает (Choice) среди уже предложенных вариантов, советник (OpenAI-совместимый чат, по умолчанию DeepSeek через ForgetAPI) решает только спор Jev с правилами и пишет причину. Всё идёт через валидатор правил; мнение модели — отдельная строка журнала. Ключи в `.env`, не в settings.json | Паттерн LLM Advisor из Maxxoto/Dota-OpenHyperAI-Agent (асинхронно, ограниченный вес, валидация, таймаут, fallback, журнал) переписан на Python, код не копировался. Решения пользователя (2026-11-07): Jev с typesafe.ai, DeepSeek через ForgetAPI, без Groq, ключи в .env |
| C21 | Послематчевый разбор: сначала детерминированный отчёт с evidence_ids и certainty, ИИ — только поверх него; ссылка ИИ на несуществующее доказательство отбрасывается. Один отчёт на матч и вид (facts/ai), цели — до трёх. Советы оцениваются по итогу, а не по строкам журнала | ТЗ F6: факты отдельно от интерпретаций, без причинности по одной корреляции, ошибки агента рядом с ошибками игрока |

## Что готово, что расширить, что получить нельзя

| Возможность | Статус | Где / почему |
|---|---|---|
| Установка, удаление, токен и health GSI; Setup-страница | готово | `gsi/installer.py`, `/api/gsi/*`, `web/src/pages/Setup.tsx` |
| Запись GSI, replay, демо-матч | готово | `gsi/recorder.py`, `gsi/demo.py`, `/api/replay`, `/api/demo` |
| Статус Copilot: подключение, режим, патч, источники полей, ошибки, `stale` | готово | `/api/copilot/status`; на `/compact` — метка «Демо» / «Запись» / «Данные устарели» / «Нет данных» |
| Свой герой, сторона, баны, союзники после загрузки, замеченные враги | готово | `fix-live-draft`, `live/engine.py` |
| Пики врагов во время ranked-драфта | из GSI **нельзя**; есть чтение экрана (по желанию) и ручной ввод | Блок `draft` у игрока пустой (проверено на записях автора). `d2bg-cv` читает видимые пики; точность на реальных экранах **не измерена** — нужны скриншоты |
| Предметы, кулдауны и позиции врагов в своей игре | **нельзя** | GSI присылает их только зрителю. Использовать запрещено ТЗ и SAFETY |
| Подбор героя (контрпики, синергия, мета, пул, позиции, баны) | готово | `draft/advisor.py`, `draft/service.py` |
