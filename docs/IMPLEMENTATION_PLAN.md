# План реализации

План опирается на аудит из `docs/ARCHITECTURE.md` и на ТЗ (`DOTA2_COPILOT_TZ.md`). Каждый этап —
отдельный PR со своими тестами. Исходные проверки d2bg должны оставаться зелёными: `uv run pytest`,
`ruff check`, `ruff format --check`, `mypy`, а в `web/` — `npm run lint`, `typecheck`, `test`, `build`.

### Этап 3 — драфт (нужно решение пользователя)

`docs/SAFETY.md` и `tests/d2bg/test_safety.py` базового проекта запрещают захват экрана (`mss`) и
`ctypes`. Dota Assist использует и то и другое, а ещё `keyboard`, `PyQt6`, Flask и свой GSI-сервер.
Варианты:

- **Рекомендуемый:** ручной ввод (уже есть на странице Draft: поиск, клавиатура, вставка списка)
  плюс распознавание **скриншота, который пользователь вставил сам** (Win+Shift+S, затем Ctrl+V на
  странице Draft). Из Dota Assist берётся только логика `recognizer.py`: OpenCV `matchTemplate`,
  порог, отрыв от второго кандидата. Захвата экрана в коде нет, запрет в `test_safety.py` остаётся.
  OpenCV ставится как необязательная зависимость (`uv sync --extra cv`).
- Автоматический захват экрана отдельным процессом вне пакета `d2bg`, со своим safety-тестом
  (захват разрешён, ввод и память запрещены). Удобнее во время драфта, но меняет политику
  безопасности базового проекта.

В обоих вариантах неуверенный слот показывается как `?` и исправляется вручную, результат — запись
`draft_observations` с `confidence` по слотам.

### Этап 4 — облачные провайдеры

- `DecisionProvider` с реализациями `baseline`, `jev`, `groq`, `hybrid`. Паттерн взят у
  Dota-OpenHyperAI-Agent: модель только переранжирует допустимых кандидатов, вес не больше 0.5,
  ожидание ограничено, бюджет вызовов на матч ограничен, при любой ошибке — тихий fallback на baseline.
- Таблица `provider_calls`: latency, токены, стоимость, статус, без ключей.
- Ключи — через keyring (Windows Credential Manager), в UI только `configured=true/false`.
- Все платные API в тестах замоканы (`respx`), ответы 401, 402, 429, 5xx, timeout, невалидный JSON.
- **Проверить до начала работы:** API Jev (в ТЗ ссылка на `docs.typesafe.ai`, методы
  Choice / Score / Noul) и текущие модели Groq и DeepSeek. На этапах 0–1 эти API не проверялись.

### Этап 5 — послематчевый тренер

Переиспользовать `matches/postgame.py`, `matches/review.py`, `profile/analytics.py`. Связать матч
OpenDota с `gsi_events_index` и `recommendations` по `match_id` и игровому времени. Детерминированные
находки с `certainty` и `evidence_ids`. DeepSeek получает только отобранные факты. Таблицы
`postmatch_metrics`, `postmatch_findings`, `practice_goals`.

### Этап 6 — UX и сборка

Страницы `Copilot`, `Review`, `Providers`; отключение облака и категорий подсказок; удаление истории;
экспорт диагностики без секретов; проверка на чистой Windows 10; инсталлятор. Always-on-top
(`d2bg window` уже есть, но не проверен) и локальный парсер `.dem` — отдельными PR.

## Известные ограничения после этапа 2

- Pro-сборки в снимке данных не разделены по позициям. Совет одинаков для любой позиции героя.
- Правила рангов стандартные. Герои с нестандартными рангами (Invoker) не получают совета по таким
  способностям. Это задумано: лучше без совета, чем с неверным.
- То, что таланты с 7.40 тратят отдельные очки, взято из базового проекта и самостоятельно не проверено.
- Какой из двух талантов яруса выбран, GSI не говорит. Статус такого совета — `unknown`.
- Текст «Как купить» описывает магазин Dota по памяти. Его надо сверить в игре.
- Реальных записей игр по-прежнему 2. Остальные 19 сценариев построены из демо и этих записей.
  Нужны анонимизированные записи разных героев и позиций.
- Остальной интерфейс d2bg на английском. На русском пока только панель Copilot.
- Хранение истории не ограничено. Записи GSI по-прежнему чистит Recorder (последние 20).
- Позиция известна, только если в настройках выбрана ровно одна.
